# AI 简历填表助手

一个基于 Chrome/Edge Side Panel 的浏览器扩展。

你维护一份标准化简历，扩展负责在网页里扫描表单字段，用大模型只做“字段映射”，再由本地脚本执行确定性填充。默认不会自动提交表单。

在简历配置页点击“管理字段”，可按分区新增、编辑或删除内置及自定义字段，支持单行、多行、日期、下拉、邮箱、电话和网址。每份简历独立配置，同一分区的多条经历共用字段定义。修改后点击“应用此字段”“完成”，再保存简历；取消会放弃本次字段管理的修改。删除会清除该分区全部记录的对应内容；类型或选项变更导致内容不兼容时，会先提示确认。字段配置随模板复制、备份保留，AI 预填与自动填表均使用当前配置。

## 🎯 这项目解决什么问题

大多数网申/招聘表单都有几个共同问题：

- 同一份信息要反复填写
- 不同网站字段命名不统一
- 某些页面用了自定义控件、日期面板、单选/多选组，脚本很难稳定处理
- 纯“让 AI 直接操作页面”不够可控，也不方便排查失败原因

这个项目的做法不是让 AI 直接乱填页面，而是拆成两步：

1. 先把你的简历整理成固定 schema
2. 再让 AI 只判断“页面字段应该对应简历里的哪个路径”

映射完成后，真正的写值、触发事件、匹配选项、处理日期控件，都在内容脚本里本地执行。

这让行为更可控，也更容易调试。

## ✨ 核心能力

- 标准简历 schema：内置较完整的简历结构，覆盖基本信息、联系方式、教育经历、实习、工作、项目、校园经历、技能证书（含语言）、个人成果、补充信息等
- AI 导入简历：支持粘贴原始简历文本，或者上传带文字层的 PDF，自动抽取并整理为标准简历 JSON
- 三种填充模式：
  - 整页填充：覆盖当前页面可识别字段
  - 增量填入：跳过已经有值的字段
  - 选区填入：先框选页面区域，只填选区内字段
- 多控件支持：`input`、`textarea`、`select`、`radio group`、`checkbox group`、`contenteditable`
- 日期控件适配：对部分只读日期输入框和日期面板做了特殊处理
- 深度扫描：填充前自动展开明确标记为“展开/查看更多”的折叠区块，再扫描新增字段
- 字段映射缓存：同一页面结构会复用本地映射缓存，减少重复调用模型
- 运行诊断日志：侧边栏展示关键日志，支持把完整会话自动导出到 `debug-logs/`
- 独立简历配置页：复杂简历字段不挤在侧边栏里，支持打开宽页面编辑
- 多模型配置：内置 DeepSeek，也可以配置任意 OpenAI 兼容接口
- 多简历模板：可维护多份标准简历（如测开 / 游戏开发 / 普通开发），填充前按需切换，支持新建、复制、重命名、删除
- 备份与恢复：一键导出 / 导入全部模板为 JSON，方便换设备或回滚
- 填写要求文档：逐页采集招聘表单要求，AI 对照本地简历分析资料缺口，保存到本地文档库

## 🧩 适合什么场景

- 校招/社招网申表单
- 企业招聘官网
- 需要频繁重复填写的申请表
- 希望保留人工确认，不想自动提交的人

## 🚫 不做什么

- 不自动提交表单
- 不处理 `input[type="file"]` 的自动上传
- 不内置 OCR，扫描版 PDF 需要你先 OCR
- 不依赖后端服务，不上传到你自己的服务器

## ⚙️ 项目怎么工作

### 1. 标准简历

扩展先维护一份固定 schema 的简历数据，模型配置和 API Key 都存储在当前设备的 `chrome.storage.local` 中，不会通过 Chrome Sync 跨设备同步。

简历及填写要求文档仅保存在本机，不再提供跨设备同步。简历管理保留 JSON 导入/导出；本地多窗口修改冲突会保留副本。

### 移除同步与历史云端清理

新版首次运行会删除本扩展的历史云端简历键（`resumeSyncV1:` 及旧版简历键），随后读取核验。不会删除模型配置或现有本地简历。此迁移不再生成备份，请保留此前下载的备份。请先停用或更新其他设备的旧版扩展，以免重新上传。

“简历管理”显示清理结果，失败可重试；清理失败不影响本地编辑。源码修改本身不会清理浏览器数据，需在扩展管理页重新加载新版后执行。核验成功后不再访问简历云端存储。保留 `alarms` 权限仅用于清除旧同步定时任务，不创建新任务。

本地简历位于 `chrome.storage.local` 的 `resumeTemplates` 和 `activeResumeTemplateId`；文档库位于 `resumeRequirementDocumentsV1`。不在项目目录生成个人资料文件。

### 填写要求文档

1. 打开招聘表单，在侧边栏点击“分析填写要求”，读取当前页面；也可从简历配置页进入“填写要求文档”。
2. 新建文档或选择已有文档，手动切换网页步骤、展开分区，点击“读取当前页面并追加”。相同地址再次采集时可替换指定记录或保留为新步骤。
3. 采集包含字段名称、分区、必填标记、选项、格式/长度限制和关联说明；同时读取控件当前已填值（含只读和禁用控件），不读取密码、隐藏项、附件内容或完整 HTML，来源 URL 移除查询参数和片段。仅覆盖当前主页面扫描器可访问的控件，iframe、未加载和不支持的控件可能遗漏。
4. 选择已保存的简历并点击“AI 分析”。所选简历字段、页面要求和网页已填内容会发送给当前配置模型；结果区分页面要求、来源证据及补充建议，不自动改写简历。没有证据的限制视为未知。
5. 检查预览后保存。支持重命名、删除、重新分析、单篇 Markdown 导出、当前草稿 JSON 导出，以及文档库 JSON 导出/恢复。标识冲突的导入保留副本。文档与简历备份分别管理。
6. 分析结果下方提供“审批简历修改建议”，可新增自定义字段、调整字段名称/类型/选项，或补全、修改字段内容。每项展示修改前后、理由和网页来源；所有建议默认不勾选，编辑后需重新勾选。
7. 确认目标简历，勾选需要的建议，点击“批准并应用到……”统一保存。单纯生成、预览、保存文档不会修改简历。应用记录随文档 JSON 和 Markdown 导出保留，包含实际修改和时间。

采集证据和完整分析默认折叠，已有资料默认不重复展示。修改建议以摘要卡片呈现，每页 6 项，可搜索或按分区筛选，展开后查看来源、完整差异及编辑内容；跨页勾选会保留，审批按钮显示总选择数。明确相同的建议合并来源，已有同名字段的重复新增及内容/定义没有变化的建议自动排除。不同经历、不同建议值和不同页面限制分别保留。

同一分区的多条经历共用字段定义；修改类型或选项前会展示全部受影响记录，不兼容内容需要先输入有效替代值。内容建议必须定位到具体经历，信息不足时需要手动选择或补充；本功能不删除字段/经历、不新增分区或经历。重复或冲突建议只能选择一个版本。

审批绑定分析时的简历快照。简历或文档在其他窗口发生变化时，应用会停止，需重新分析并审批。所选修改和审批记录一次保存，失败不写入任何所选修改；重复提交不会重复执行。同一批次应用后，未选建议需重新分析再审批。历史文档仍可查看，重新分析后才会生成可审批建议。

AI 失败保留当前页面内的草稿，已有保存版本不受影响；关闭页面前请保存或导出。容量不足时可直接导出当前结果。每份文档最多 50 页、每页最多 1000 个字段；每批最多分析 20 个字段，模型明确报告输出截断时自动缩小批次；支持说明文字、代码块和尾逗号的 JSON 解析，格式或覆盖错误会自动重试当前批次一次。单批请求超过 180000 字符时需要缩减输入。旧文档未采集过已填值，需重新读取并替换页面记录。

**源码版升级迁移：** 本版在 `manifest.json` 中固定了扩展公钥，使不同目录、设备上的扩展 ID 一致。旧版没有固定公钥，升级后可能变成另一个扩展，无法直接读取旧 ID 下的本地数据。请先在旧版导出全部简历 JSON，并自行记录本机模型配置和 API Key，再加载新版、导入简历并重新配置模型；确认数据完整后再移除旧扩展。不要修改或重新生成仓库中的 `key`。仓库仅包含公钥，不包含私钥。

这一步的价值是把“原始简历文本”变成“可复用字段目录”，后面的映射和填充都围绕它进行。

### 2. 页面字段扫描

内容脚本会扫描当前页面可填写控件，并尽量提取：

- 字段标签
- placeholder
- 选项列表
- 上下文文本
- 附近标签
- 所在区块语义

项目里专门写了字段标签提取、区块语义判断、日期运行时判断等辅助模块，不是单纯只看 `label`。

### 3. AI 只做字段映射

发送给模型的是：

- 当前页面字段列表
- 已填写的标准简历字段目录
- 允许的 transform 规则

模型只返回“某个页面字段对应哪个 `resumePath`”，例如：

- `personal.email`
- `educations.0.school`
- `internships.0.company`

而不是直接返回一整页最终表单值。

### 4. 深度扫描只展开已有区块

整页填充前，扩展会识别带有“展开”“查看更多”或明确折叠状态的控件，等待新增字段渲染后再开始扫描。为了避免误操作，带有“添加”“新增”“新建”或加号语义的控件不会被自动点击；选区填入也不会触发深度扫描。

### 5. 本地确定性填充

拿到映射后，扩展会在浏览器里本地完成：

- 取值
- 日期/手机号拆分
- 单选/多选匹配
- 下拉选择
- 输入事件与 change 事件触发

这一步不依赖模型，行为更稳定。

## 🚀 快速开始

### 1. 安装扩展

1. 打开 `chrome://extensions/` 或 `edge://extensions/`
2. 开启“开发者模式”
3. 点击“加载已解压的扩展程序”
4. 选择当前项目目录
5. 点击扩展图标，打开侧边栏

这个项目没有构建步骤，源码目录可以直接加载。

### 2. 配置模型

侧边栏右上角进入设置。

模型配置只保存在当前浏览器的本地扩展存储中，API Key 不会通过消息传给页面脚本；后台会根据模型 ID 读取配置并代理请求。

默认内置一套 DeepSeek 配置模板，你也可以改成任意 OpenAI 兼容接口。当前实现调用的是：

- `POST /chat/completions`

常见示例：

- `Base URL`: `https://api.deepseek.com/v1`
- `Model`: `deepseek-chat`
- `API Key`: 你自己的 key

### 3. 准备标准简历

点击侧边栏的“编辑简历”，在独立简历页维护资料：

- 手动填写，或展开“AI 预填”粘贴文本、上传带文字层的 PDF；预填后检查并保存。
- 顶部切换简历或新建简历；“更多”提供复制、重命名、删除和重新加载。
- “简历管理”统一提供全部简历 JSON 导入、导出和历史云端清理状态。导入覆盖全部简历；导出会先保存当前修改，保存失败则停止导出。
- “联系方式”同时包含地址、紧急联系人和在线资料。“技能证书”包含技能、证书、语言三个小组。“个人成果”记录成果名称、成果简介和成果日期。
- 日期通过年、月、日下拉框选择，允许仅年或年月；不确定的月份和日期可留空。不能识别的旧日期会保留原值，重新选择或清空后才替换。

旧版“证件与资格”数据保留在备份中，页面不再显示，也不参与自动填充。旧论文、专利文本会完整迁入个人成果，不猜测标题拆分或日期；成果已满十条时，旧文本保留，腾出位置后迁入。

保存后，在侧边栏选择本次使用的简历并填充网页。

### 4. 在网页里执行填充

打开目标表单页后，可在侧边栏选择：

- `开始填充`
- `增量填入`
- `选区填入`

扩展声明 HTTP/HTTPS 页面访问权限，以便侧边栏在切换任意普通网页标签页后仍能读取并填写当前页面。页面脚本不会常驻网站，只会在你点击填充操作后通过 `scripting` 权限动态注入当前页面。发给模型的页面 URL 会自动移除 query/hash，避免把临时参数和 token 带出。

填充完成后，请自己检查并手动提交。

## 🧠 当前实现里值得注意的设计点

### 1. 映射缓存是按“页面结构签名”做的

项目不是简单按 URL 缓存，而是会结合字段种类、标签、placeholder、section 信息等生成签名。

这能避免“同一页面字段已经变了，但还错误复用旧缓存”的问题。

### 2. 侧边栏日志和完整诊断日志分层显示

UI 里只显示关键过程日志，冗长的结构化诊断不会全部堆到面板里。

如果你授权项目目录，完整会话日志会自动导出到：

- `debug-logs/`

适合排查“为什么这个网站没映射上”或“为什么这个日期控件没填进去”。

### 3. 项目偏向校招/中文网申语义

schema 和映射提示词里，对这些内容做了额外强化：

- 教育经历
- 实习经历
- 校园经历
- 学历类型 / 培养方式 / 实验室 / 导师 / 学号等字段

如果你的主要场景是中文招聘站，这一套会比通用型 schema 更顺手。

## 📌 支持与限制

### 已支持

- 文本输入框
- 文本域
- 下拉框
- 单选组
- 多选组
- `contenteditable`
- 部分只读日期输入框与日期面板
- 整页/增量/选区三种填充模式

### 明确限制

- 文件上传字段不能自动写入
- 扫描版 PDF 没有文字层时无法直接导入
- 跨域 `iframe` 内的字段可能无法识别或填写
- 极端自定义控件仍可能需要单站点适配
- 深度扫描依赖按钮的可访问性属性、折叠状态或明确文本；站点完全没有这些语义时仍需要手动展开
- 刚重载扩展后，旧页面里可能还挂着旧版 content script；刷新页面一次再试最稳妥

## 🗂️ 项目结构

```text
.
├── manifest.json               # Chrome MV3 配置
```

## 🔒 隐私与安全

请默认按“简历数据是敏感信息”来理解这个项目。

- 你的 `API Key` 和模型配置仅保存在当前浏览器的本地扩展存储里；简历和填写要求文档仅保存在本地，AI 分析时相关内容发送给你配置的模型
- 用于字段映射和简历导入的内容会发送到你配置的模型接口
- API Base URL 默认必须使用 HTTPS；仅允许 `localhost`、`127.0.0.1`、`::1` 的本机 HTTP 调试地址
- 诊断日志会对常见个人信息脱敏，导出目录最多保留 50 个 JSON 日志文件
- 发送内容可能包含：简历文本、页面 URL、页面标题、字段标签、选项和上下文文本
- 项目默认不会自动提交表单

如果你不希望任何简历内容离开本地，就不要配置在线模型接口。
